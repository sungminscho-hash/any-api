# any-api — 어떤 웹 화면이든 API 로 바꾸는 방법과 자동화 계획

이 문서는 한 회계 SaaS 의 비공식 API 20여 개를 손으로 뚫었던 사내 작업에서 **반복된 절차를 뽑아
일반화**한 것이다. 그 작업의 사이트별 세부(서명 알고리즘, 자격증명 위치, 엔드포인트)는 사내 문서에만
있고 여기에는 싣지 않는다. 여기 있는 것은 어느 사이트에도 적용되는 절차·판정 기준·자동화 설계다.

같이 읽을 문서: `pipeline.md`(단계별 설계·레시피 스키마), `roadmap.md`(일정·완료 기준·리스크).

용어: **허브**는 검토를 통과한 API 레시피를 한 곳에 모아 두고, 여러 프로젝트가 같은 방식으로 꺼내 쓰며,
자주 쓰는 응답을 캐시해 주는 공용 계층을 뜻한다.

---

## 1. 결론 먼저

- **원리상 가능하다.** 브라우저의 버튼 하나는 결국 HTTP 요청 하나(또는 몇 개)다. 로그인된 세션의
  자격증명을 얻고 요청을 그대로 재현하면 어떤 사이트의 어떤 조회·다운로드도 코드로 부를 수 있다.
- **하지만 "자동"은 절반만 맞다.** 사이트마다 난이도가 갈리고, 난이도를 가르는 건 §3 의 네 가지 질문이다.
  T0 는 캡처 → 재생까지 완전 자동, T2 는 서명 역공학에 사람이나 LLM 이 개입, T3 는 API 화를 포기한다.
- **"검토 후 허브"가 핵심 산출물이다.** 뚫는 것보다 뚫은 결과를 검증된 레시피로 남기고 다른 프로젝트가
  재발견 없이 쓰게 하는 것이 목적이다. 자동화는 레시피를 만드는 시간을 줄이는 수단이다.
- **법적·계약적 허용 범위를 먼저 확인한다.** 비공식 API 는 상대 서비스와 합의된 것이 아니다.

## 2. 한 화면이 API 가 되기까지 — 실제로 밟은 절차 (일반화)

| # | 절차 | 실제로 한 일 | 걸린 것 |
|---|---|---|---|
| 1 | **자격증명 위치 찾기** | 로그인한 탭의 콘솔에서 `document.cookie`·`localStorage`·`sessionStorage` 를 찍어 서명·인증에 쓰이는 값이 JS 로 읽히는지 확인. 프런트가 직접 서명을 계산하는 사이트라면 그 값은 반드시 JS 가 닿는 곳에 있다 | 반나절 |
| 2 | **요청 캡처** | DevTools 에서 "Copy as cURL". 화면마다 한 번 | 화면당 10분 |
| 3 | **요청마다 바뀌는 값 가려내기** | 같은 버튼을 두 번 눌러 비교 → timestamp·nonce·서명 헤더가 매번 다름을 발견 | 1시간 |
| 4 | **서명 역공학** | 원격 디버깅(CDP)으로 웹팩 모듈 수천 개를 확보 → 서명 헤더 이름 리터럴을 포함한 모듈 수십 개 중 계산 함수 발견 → 다른 언어로 재현 → 실캡처 값과 비교해 일치 | 며칠 |
| 5 | **재생·파라미터 검증** | 파라미터를 하나씩 틀리게/비워서 보냄 → "이 키가 없으면 오류 대신 0건", "빈 문자열은 필터 없음이 아니라 해당 없음", "회사 선택은 이 키 하나만 봄", "모르는 파라미터는 조용히 무시" 같은 함정 발견 | 엔드포인트당 반나절 |
| 6 | **문서화·검토** | 요청/응답/⚠️함정/미확인 을 적고, "확인됨"은 재현된 것만 | 상시 |

사람이 오래 붙잡힌 곳은 4번(서명)과 5번(파라미터 함정)이다. 그리고 두 곳 모두 **"두 번 캡처해서 비교" /
"하나씩 빼고 다시 보내서 비교"** 라는 기계적 방법으로 대부분 대체된다. 그게 자동화의 지렛대다.

## 3. 난이도 등급 — 네 가지 질문

| 질문 | 예 | 아니오 |
|---|---|---|
| Q1. 인증이 **정적인 값**(쿠키·Bearer·세션 ID)만으로 되나? | T0 후보 | Q2 |
| Q2. 바뀌는 값이 **페이지 안에 이미 있는 토큰**(CSRF meta, hidden input, storage)인가? | T1 | Q3 |
| Q3. 바뀌는 값이 **프런트 JS 가 계산하는 서명/암호화**인가? | T2 | Q4 |
| Q4. 봇 차단(Turnstile, Akamai 등), TLS/기기 지문, CAPTCHA, 앱 attestation 이 있나? | T3 | — |

| 등급 | 뜻 | 자동화 | 예 |
|---|---|---|---|
| **T0** | 세션 쿠키/토큰만 붙이면 재생됨 | 완전 자동 | 사내 ERP 엑셀 다운로드, 단순 조회 XHR |
| **T1** | 페이지에서 토큰 하나 더 읽어야 함 | 자동. 토큰 추출 규칙만 기록 | Django/Spring CSRF |
| **T2** | 요청마다 서명 계산 | 반자동. 후보 탐색·검증 자동, 포팅은 LLM+사람. 통과 기준 100% 일치 | 일부 회계·금융 SaaS |
| **T3** | 서버가 브라우저 자체를 검사 | API 화 불가. 브라우저 내 재생 또는 UI 자동화 | 봇 차단 뒤의 공개 포털 |

판정법: 같은 버튼을 두 번 눌러 두 요청을 diff. 달라진 필드가 (a) 없으면 T0, (b) 페이지 어딘가에 그대로
있으면 T1, (c) 어디에도 없으면 T2. T3 는 재생 시 403/429/챌린지 페이지로 드러난다.

## 4. 자동화 파이프라인 (요약)

```
[0 승인]   대상 사이트·계정·범위(읽기 전용) 확인 ── 사람
[1 record]  로그인된 브라우저에서 "그 버튼"을 누르고 요청·응답·쿠키·스토리지·DOM 기록
            ── Playwright / ego-lite / Chrome CDP / HAR import
[2 analyze] 두 기록 diff → 동적 필드 → 등급 판정, 자격증명 캐리어 표시 ── 자동
[3 sign-hunt] (T2) 번들 리터럴 검색 → 후보 → LLM 포팅 → 캡처값 대조 ── 반자동, 100% 일치 게이트
[4 verify]  새 nonce 로 재생 → 스키마·건수 비교, 파라미터 민감도 → 함정 자동 추출 ── 자동
[5 emit]    recipe.json + 클라이언트 + 문서 ── 자동
[6 review]  법무/보안/개인정보/읽기전용/문서 규칙 체크리스트 ── 사람 (게이트)
[7 publish] 허브: 카탈로그 + (선택) 게이트웨이·캐시 ── 자동
[8 watch]   주기 재검증 → 깨지면 1 로 ── 자동
```

도구별 역할:

- **ego-lite** — 기록기. 사용자의 로그인 상태를 물려받은 격리 Space 에서 에이전트가 화면을 누르고
  `cdp('Network.enable')` + `drainEvents()` 로 요청·응답을 받으며 `js()` 로 번들·스토리지를 덤프한다.
  사용자 탭을 건드리지 않는다. 현재 macOS 전용.
- **Playwright + 로컬 Chrome** — 전 플랫폼 기록기. 격리 프로필에서 사용자가 직접 로그인(비밀번호 미취급).
  `context.newCDPSession()` 으로 같은 CDP 를 쓴다.
- **사용자 Chrome + `--remote-debugging-port`** — 서명을 찾을 때 번들을 덤프하는 방식. 기록 전용.
- **Aside** — 개발자 접점(CDP·CLI·MCP·API)을 공개하지 않은 AI 브라우저. 파이프라인에 프로그램으로 묶을 수
  없다. T3 사이트의 최후 실행기, "어느 메뉴에 그 버튼이 있나" 탐색 보조, 루틴으로 화면 변화 감시에 쓴다.
- **Claude Code / Codex** — 오케스트레이터.

## 5. 허브 — 검토를 통과한 레시피가 사는 곳

### 5.1 왜

여러 프로젝트가 같은 사이트를 따로따로 뚫는 것을 막는다. 한 번 검증된 서명·함정이 모두에게 전달되고,
자격증명 정책을 한 곳에서 강제하며, 하루에 한 번 바뀌는 마스터 응답을 캐시해 상대 서버 부하와 차단
위험을 줄인다.

### 5.2 두 층

| 층 | 형태 | 내용 |
|---|---|---|
| **카탈로그** (필수) | Git 저장소 | `recipes/<site>/<endpoint>/{recipe.json, client, doc.md, review.json}`. 버전·검토자·검증일. 소비 프로젝트는 패키지/서브모듈로 가져다 씀 |
| **게이트웨이** (선택) | HTTP 서비스 | `POST /v1/<site>/<recipe>` → 호출자 세션(메모리)으로 레시피 실행 → 정규화 JSON/xlsx. 마스터성 응답만 TTL 캐시. 감사 로그. 속도 제한 강제 |

거래 데이터는 캐시하지 않는다. 캐시 대상은 마스터(코드표·거래처·조직)와 메타(회계기간)뿐이다.

### 5.3 자격증명 원칙

- 디스크 저장 금지, 메모리·세션 TTL 만. 로그·예외에서 마스킹.
- 레시피에는 자리표시자만. 실값이 커밋되면 CI 가 막는다.
- 읽기 전용이 기본. 쓰기 레시피는 별도 카탈로그 + 별도 승인.

## 6. 하지 않는 것 / 먼저 확인할 것

- **약관·계약.** 자동화·스크래핑 금지 조항, 계정 사용 동의를 0단계에서 확인한다. 못 하면 올리지 않는다.
- **차단 우회 금지.** T3 면 CAPTCHA 풀기·지문 위조를 시도하지 않는다. 사용자가 보는 그대로의 UI 자동화만.
- **속도 제한.** 레시피마다 최대 빈도를 적고 강제한다. 계정 잠금은 업무 중단이다.
- **개인정보.** 응답에 민감 필드가 있으면 레시피에 표시하고 보존 정책을 검토 게이트에서 정한다.

   파이프라인이 같은 서명·같은 함정을 스스로 찾아내는지로 자동화 품질을 잰다.
