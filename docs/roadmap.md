# 로드맵 — 단계, 완료 기준, 리스크

각 단계는 완료 기준을 통과해야 다음으로 간다. 기간은 한 사람 기준 추정. 파일럿은 **이미 손으로 뚫어 둔
사이트를 다시 자동으로 뚫는 것**이라 정답이 있는 상태에서 자동화 품질을 잰다.

## 0단계 — 범위와 승인 (1일)
- 대상 사이트 목록과 약관·계약 확인 기록. 자격증명 정책(디스크 저장 금지·TTL·마스킹·읽기 전용 기본) 합의.
- **완료:** 사이트별 허용/불가/조건부 표와 정책 문서 커밋.

## 1단계 — `record` + `analyze` (Playwright) (3~4일)
- 격리창 로그인, CDP 세션으로 응답 바디 수집, `--import har`, diff 기반 analyze.
- **완료:** 파일럿 화면을 두 번 기록 → timestamp·nonce·서명 헤더를 동적으로, 그중 서명만 unresolved 로 잡아 T2 판정. 캡처 폴더에 자격증명 실값 없음.

## 2단계 — `sign-hunt` (3~5일)
- 번들 덤프, 리터럴 검색, 후보 추출, LLM 포팅, 벡터 100% 일치 루프.
- **완료:** 정답 문서를 보여주지 않고 캡처만으로 서명을 찾아 포팅, 실캡처 3건 이상 일치.

## 3단계 — `verify` + `emit` (3~4일)
- 재생, 민감도 표, 완전성 규칙, recipe/client/doc 생성.
- **완료:** 파일럿 엔드포인트 5개 레시피 자동 생성. 민감도 표가 손으로 찾았던 함정(필수 키·빈값 0건·선택자 키·무시되는 키)을 사람 개입 없이 재발견. 생성 문서에 "추정" 0건.

## 4단계 — 두 번째 사이트 (1주)
- T0/T1 하나, 가능하면 T3 하나.
- **완료:** T0 는 record→publish 무인 통과. T3 는 `ui-fallback` 판정, 우회 시도 없음.

## 5단계 — 허브 1차: 카탈로그 (1주)
- `recipes/` 구조, `review.json` 게이트, 자격증명 스캐너 CI, 패키지 배포.
- **완료:** 두 번째 프로젝트가 코드 복사 없이 같은 레시피로 데이터를 받음.

## 6단계 — ego-lite 어댑터 (Mac, 2~3일)
- `record --driver ego`. `drainEvents()` 범위·파일 쓰기·바디 획득을 실환경에서 확인.
- **완료:** 재로그인 없이 격리 Space 에서 1단계와 같은 캡처 폴더 형식이 나옴.

## 7단계 — 허브 2차: 게이트웨이·캐시·watch (2주, 선택)
- **완료:** 두 프로젝트 이상이 게이트웨이 호출, 마스터 캐시 적중, 스키마 변경 알림 재현.

## Aside 의 자리
필수 구성요소가 아니다(프로그램 연결 접점 없음). (1) T3 사이트의 최후 수단, (2) 착수 전 화면 탐색 보조,
(3) 루틴으로 화면 변화 감시. 접점이 공개되면 6단계와 같은 어댑터를 추가한다.

## 리스크

| 리스크 | 대응 |
|---|---|
| 약관 위반·계정 정지 | 0단계 게이트, 읽기 전용, rateLimit 강제, 우회 금지 |
| 서명 역공학 실패(난독화·WASM·서버 챌린지) | 브라우저 내 재생(`browserFetch`)으로 강등, 그래도 안 되면 UI 자동화 |
| 사이트 개편 | watch 로 조기 감지, `broken` 표시, record 재실행 |
| 자격증명 유출 | 캡처·레시피·로그 스캐너, 메모리 전용, TTL, 마스킹 |
| ego-lite Windows 미지원 | Playwright 를 기본으로, ego 는 Mac 에서 병행 |
| 민감도 테스트의 서버 부하 | 읽기 전용만, 간격 1초, 변형 수 상한 |
| "확인됨" 남발 | emit 이 verify 로그 항목에만 붙임 |
